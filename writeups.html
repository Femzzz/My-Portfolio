Building a Full Home SIEM Pipeline: Correlating Suricata NIDS & Sysmon Telemetry in Wazuh

Modern security operations rely on visibility across both the network perimeter and individual host endpoints. In this lab write-up, we walk through architecting an isolated enterprise SOC simulation capable of detecting lateral movement and automated brute-force attacks in real time.

1. Telemetry Architecture

The environment is segmented behind a pfSense perimeter firewall. Network traffic traversing the LAN interface is mirrored to Suricata operating in NIDS mode, while endpoint process creation and registry modifications are captured via Sysmon and forwarded through the Wazuh agent.

# /var/ossec/etc/ossec.conf — Suricata JSON ingestion
<localfile>
  <log_format>json</log_format>
  <location>/var/log/suricata/eve.json</location>
</localfile>

2. Detection Engineering & Takeaways

By correlating Suricata's eve.json alerts with Sysmon Event ID 1 (Process Creation), noisy network scans are separated from genuine exploitation attempts—reducing false-positive alert fatigue while maintaining sub-second response triggers.
